# State-corpus: command sequences and oracle traces

This directory contains the command-sequence corpus for the Rust↔TS differential state-migration test harness.

## Structure

- `sequences/` — JSON command sequences authored by hand (one invariant or variant per file)
- `oracle/` — canonical driver output committed alongside the sequences; generated by `scripts/gen-state-oracle.mjs`
- `oracle-summary/` — parallel oracle set for the renderer IPC read-view; generated alongside `oracle/` by the same script

## Generating / regenerating oracles

```
cd apps/desktop
node scripts/gen-state-oracle.mjs
```

The script runs each sequence through the Rust `replay_driver` bin **twice per emit mode** and asserts byte-identical output (determinism gate). On success it writes `oracle/<name>.json` and `oracle-summary/<name>.json` and prints `ok  <name>`. Fail output prints `NONDETERMINISTIC (<emit>): <name>` and exits nonzero.

### oracle-summary/

Parallel oracle set for the renderer IPC read-view (`commands::build_project_summary`
→ TS `summary.ts buildProjectSummary`), produced by `replay_driver` with
`REPLAY_EMIT=summary`. One file per sequence, same step structure as `oracle/` but
each step carries `summary` (the `ProjectSummary` view) instead of `state` (the
`.vproj` snapshot). Gated by `__tests__/summary.differential.test.ts`. Filesystem
fields (`available`/proxy paths) are `false`/`null` on both sides (fixture media
paths don't exist). Phase 3a.

## Known gaps — invariants NOT covered by this corpus

The driver's ref-capture is generalized: every id-returning op (`add_layer`, `add_track`, `add_marker`, `duplicate_layer`, `groups_create`) captures its result under a command `ref`, so groups, custom tracks, and markers are all addressable and differential-gated. The items below remain deferred.

### 1. History cap >200 ops
Authoring a sequence of >200 commands to exercise the history ring cap would produce large JSON files and long runtimes with marginal differential value. Deferred unless a specific cap-boundary bug surfaces.

### 2. Duplicate with negative / zero offset edge cases
Duplicate with a negative `t_offset_us` that would produce a negative start time is not tested (driver behaviour on this path is unspecified).

### 3. Marker `color` patch
`update_marker`'s `color` field is unit-tested (`mutations/markers.test.ts`) but NOT differential-gated — the driver builds `MarkerPatch { color: None }` and the corpus omits color.

### 4. Caption tracks
These mutation categories require corpus extensions and Rust replay-driver support; deferred to later slices.

Motif `update_layer_params` content-window clamp (motif_cap_us) — deferred (needs motif-catalog support in the harness; no Motif layers in the corpus).

### media-pool mutations (Phase 3c-i)

`set-media-derivatives-*` exercise the tri-state derivative patch
(`Option<Option<PathBuf>>`: set/clear/leave) + plain-Option fields + MediaNotFound.
`set-media-workspace-paths*` set the workspace path/fingerprint (+ MediaNotFound).
`remove-media-*` cover the HYBRID command: `-unused` (unrecorded, +1 broadcast id,
durable across undo via `-unused-undo`), `-in-use-no-force` (MediaInUse, no id),
`-force-cascade` (recorded raw inline layer delete, +1 op_id), `-force-undo`
(undo restores layers + media), `-force-leaves-empty-track` (no auto-prune — the
force path bypasses `do_delete_layer`), and `-missing` (MediaNotFound, no id). Every
success seq ends with a trailing `add_track` proving the id-burn count.

### replace_state sequences

`replace-state-*.json` exercise the wholesale project swap (`do_replace_state` →
`History::reset`). They ride the existing `differential.phase2` (state) and
`summary.differential` (history reset: cursor 0 / len 1 / can_undo false) gates;
the trailing `add_track` proves the 5-id contract (3 blank ids + reset op_id +
broadcast id). `replace-state-clears-redo`/`-then-undo` prove the redo/undo stacks
are dropped (NothingToRedo / NothingToUndo).

### persistence round-trip gate

`__tests__/persistence.differential.test.ts` feeds each oracle's final-step `state`
(Rust's serde output) through the TS loader (`persistence.ts loadProjectFromJson`)
and asserts it re-serializes canonical-identically — gating the "Rust writes
project.json, TS reads it" invariant over the full corpus. Media reconcile +
quick-proxy clear are no-ops here (eligible corpus media have null path_rel/quick_proxy_path)
and are unit-gated in `persistence.test.ts`. The `set-media-derivatives-set` and
`set-media-workspace-paths` sequences set quick_proxy_path / path_rel respectively,
so they exercise `loadProjectFromJson`'s transforms and are excluded from this
identity gate (unit-gated in `persistence.test.ts`).
