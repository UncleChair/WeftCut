## Deferred (NOT in this pass) — why `src/{main,preload,renderer}` is a separate step

The fully-canonical electron-vite layout nests the main process under `src/main` and `src/preload` alongside the renderer at `src/renderer`. We are **not** doing that here because:

1. **`main.tsx` vs `main/` collision.** The renderer entry is `index.html → /src/main.tsx`. Moving the Electron main process to `src/main/` puts a `main/` directory immediately beside `main.tsx` — confusing and error-prone.
2. **Main/preload would mingle with renderer feature folders.** Without also moving the renderer into `src/renderer/`, `src/` would contain `main/`, `preload/`, *and* `components/`, `state/`, `timeline/`, … as peers — worse than the current clean separation.

Therefore the main-process move is **coupled** to the renderer move (the excluded "Phase 4"). Until both are done together, keeping the main process in a top-level `electron/` directory is a recognized, valid electron-vite layout. The natural follow-up pass is a single coordinated move:
- `electron/main` → `src/main`, `electron/preload` → `src/preload`
- renderer `src/*` + `index.html` → `src/renderer/*` (update the `@/*` alias to `src/renderer`, the electron-vite renderer `root`, and the build `input`)
