# In-repo fixture generation + audio matrix — design

## Goal

Two related changes to the media-conformance harness:

1. **Bring fixture generation into the repo, reproducibly, without committing the
   media.** Today the generator (`generate.go`) and the generated clips live in
   an external `testfile/` dir that isn't tracked, so fixtures aren't
   reproducible from a checkout. Move the generator + a generation script into
   the repo; gitignore the generated media; generate idempotently ("missing →
   generate, present → skip").
2. **Extend the audio conformance axis across the full matrix** — every shipped
   frame rate × container — instead of the single 30fps-mp4 case.

No analyzer or export-pipeline changes; this is test infrastructure + coverage.

## Layout (in-repo)

```
apps/desktop/e2e/fixtures/
  generate.go              # relocated from external testfile/ — single-clip generator
  generate-fixtures.mjs    # NEW — matrix definition + idempotent ensureFixtures()
  media/                   # GITIGNORED — generated clips land here
    .gitkeep
```

- `.gitignore`: ignore `apps/desktop/e2e/fixtures/media/` contents (commit the
  generator + script + `.gitkeep`; never the media).
- The specs' `WEFTCUT_TEST_MEDIA` default changes from the external path to the
  in-repo `apps/desktop/e2e/fixtures/media/`; an env override still wins.
- The external `testfile/` dir becomes obsolete for the harness (left in place;
  not deleted — it's the user's scratch).

## Generator + orchestrator

- `generate.go` is unchanged in logic (testsrc2 + burned-in counter + true-709
  conversion + `--audio` per-second tone track `F_k = 400 + 120·k Hz`); it just
  moves into `fixtures/`.
- `generate-fixtures.mjs` owns the **matrix definition** (single source of truth)
  and exports `async function ensureFixtures(mediaDir)`:
  - For each matrix entry `{ fps, format, audio }`, compute the expected output
    filename and, if it does not already exist in `mediaDir`, run
    `go run generate.go --fps <fps> --format <format> [--audio]` (cwd = the
    fixtures dir), then move/emit the output into `mediaDir`.
  - Idempotent: existing files are skipped, so re-runs are fast no-ops.
  - Runnable standalone (`node generate-fixtures.mjs`) and via an npm `fixtures`
    script, in addition to being called from the e2e.
- "Consistent" = deterministic content: `generate.go` uses testsrc2 + fixed
  encode params + a fixed tone formula, so regeneration is content-equivalent.
  Exact byte-identity across ffmpeg builds is NOT required — the analyzer's
  checks are tolerance-based (frame SSIM, audio alignment/drift/SNR).
- Prerequisites at generation time: `go` and `ffmpeg` on PATH (ffmpeg is already
  required by the analyzer).

## The matrix

**Source clips generated by `generate-fixtures.mjs`:**

- Video-only (`-an`, true 709), unchanged set: `30/60/120fps mp4`, `30fps mkv`,
  `30fps prores.mov`.
- Audio (`_audio`, tone markers): `test_1080p_{30,60,120}fps_audio.mp4` — three
  audio source clips, one per frame rate. (The audio track is the same 10×1s
  tones at every fps — only the video frame rate differs.)

**Audio conformance cases (in `audio_conformance.e2e.js`):** the full
3×3 cross product — source frame rate × export container:

| source | export container |
|--------|------------------|
| 30 / 60 / 120 fps `_audio.mp4` | mp4, mkv, mov |

= **9 cases**. The frame-rate axis exercises video-grid-vs-audio-timeline sync;
the container axis exercises the export mux path (chosen via export `settings`,
codec stays H.264 — valid in all three containers). Each case imports the
matching audio source, exports with `settings: { container }` to a per-case
output path (matching extension), and runs `analyze({ audio: true })`.

## e2e wiring

- `wdio.conf.mjs` `onPrepare`: `await ensureFixtures(mediaDir)` runs **before**
  the tauri build (generates any missing fixtures; fast no-op when present).
- `audio_conformance.e2e.js`: a `for (const c of AUDIO_CASES)` loop emits one
  `it()` per `{ fps, container }`. Per case: wait for hooks, create project,
  `exportClip({ mediaAbsPath: <fps source>, outputAbsPath: <…>.{ext},
  settings: { container } })`, poll the frame counter, then assert alignment +
  drift + SNR from `analyze({ audio: true })`. The `before` hook skips a case
  whose source clip is absent.
- `conformance.e2e.js` (video axis) is otherwise untouched — its fixtures just
  resolve from the new default dir.

## Pass/fail (unchanged from the audio axis)

Per case: every second aligned (dominant freq == expected), drift `|slope−1| ≤
0.01`, offset `|ms| ≤ 66` (AAC priming), per-second SNR ≥ 15 dB floor.

## What does NOT change

- `media_conformance --audio`: unchanged — the tone formula + 48 kHz are
  fps/container-independent; the audio is always 10×1s tones.
- The export pipeline, the `auto_pair_audio_on_import` behavior, the video axis.

## Out of scope (follow-ups)

- Audio variants of non-mp4 *source* containers (the source container barely
  affects the audio path; the export container is the meaningful mux axis and is
  covered via settings).
- ProRes/AV1 as an export *target* for the audio axis (AAC-in-MOV / AV1-in-MOV
  validity concerns); prores stays a video-only source-codec case.
- Multi-track / gain / fades / non-mono channel layouts.
