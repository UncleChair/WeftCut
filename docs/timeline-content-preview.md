# Timeline Content Preview

## Purpose

Timeline clips should communicate the media content they represent, not only
their layer type. The current colored-block timeline is useful for structure but
does not match common NLE expectations: editors expect video clips to show a
filmstrip, audio clips to show a waveform, still images to show the image, and
short clips to degrade cleanly instead of cramming unreadable text.

This document specifies the first implementation pass for content-aware timeline
blocks.

## Goals

- Render actual source-aware visual content inside timeline layer blocks.
- Keep existing timeline editing behavior unchanged: selection, drag, trim,
  blade, grouping, keyframes, ruler-only seek, and track resizing must continue
  to work.
- Use existing derivative jobs where possible:
  - video thumbnails generated under the media thumbnail cache,
  - waveform peaks generated by the waveform job.
- Make previews a progressive enhancement. Missing thumbnails or waveform peaks
  must never block editing.
- Keep the implementation replaceable so thumbnail density can improve later
  without rewriting the timeline block model.

## Non-Goals

- Do not increase thumbnail generation density in this pass.
- Do not introduce full timeline virtualization.
- Do not add a user-facing display-mode setting yet.
- Do not add dynamic Motif previews yet.
- Do not change preview/export compositing behavior.

## Layer Rendering Rules

### VideoClip

Video clips render a real filmstrip based on the layer's current source window:

- Use `src_in_us` and `src_out_us` as the displayed source interval.
- Map available thumbnail frames onto that interval.
- Stretch or compress the filmstrip to the timeline block width according to
  the clip's rendered duration.
- Reuse the existing ten generated thumbnails for the first pass.
- Do not pretend there is higher temporal precision than the cache provides.
  If the block is wider than the available representative frames, limited repeat
  or sparse placement is acceptable.

### Audio

Audio clips render a waveform:

- Use the layer's `src_in_us` and `src_out_us` as the displayed source interval.
- Fetch peaks with `getWaveformPeaks(mediaId)`.
- Draw the waveform on a canvas.
- Aggregate peaks to the rendered pixel width, targeting roughly one vertical
  bar per 1-2 px.
- Missing peaks render a stable center-line placeholder until the waveform job
  completes.

### Video + Audio on One Track

The existing `computeLayerSlices` behavior remains:

- visual layer in the top half,
- audio layer in the bottom half,
- single-class layers fill the full row.

The new content previews must honor those slice dimensions. A paired video and
audio clip should look like a compact NLE clip with filmstrip above waveform.

### ImageOverlay

Image clips render the source image directly when the file is available:

- Use `convertFileSrc(media.path)`.
- Use `object-fit: cover`.
- Fall back to the layer color hint if the source is unavailable.

### Color

Color layers render their actual color. If alpha is introduced visibly, use a
subtle checkerboard behind the fill; otherwise the current solid fill is enough.

### Text

Text layers render a semantic text preview:

- Show a compact content excerpt.
- Keep the layer color hint as the base fill.
- Do not attempt full text layout matching the canvas preview.

### Motif

Motif layers remain semantic blocks for this pass:

- Keep the motif/layer label.
- Keep bake status indicators.
- Do not capture dynamic Motif thumbnails in this implementation.

## Label and Chrome Rules

Content preview is the primary visual signal; labels and state chrome are
overlays.

- Wide blocks show a small label overlay near the visible left edge.
- Medium blocks show a shorter label.
- Narrow blocks hide text entirely.
- Labels should sit on a subtle translucent backing so they are readable without
  blanketing the filmstrip or waveform.
- Sticky-label behavior should remain for long clips so horizontally scrolled
  content still identifies the clip.
- Selection, hover, locked, disabled, and group indicators render above the
  content and should not heavily recolor the preview itself.
- Group indication remains a narrow left accent.

## Width-Based Degradation

Use rendered pixel width, not media duration, for display decisions:

| Width | Behavior |
| --- | --- |
| `< 16px` | Show only boundary/type color. Do not request thumbnails or waveform peaks. |
| `16-48px` | Show content texture if already available or cheap to request. Hide text. |
| `48-120px` | Show content plus a short label. |
| `> 120px` | Show content plus full label and status affordances. |

These thresholds are first-pass defaults and can be tuned with visual testing.

## Loading and Failure Behavior

Timeline content previews must be progressive:

- Video thumbnail cache not ready: render a low-contrast placeholder using
  `color_hint` and keep the label visible when width allows.
- Waveform not ready: render a center line or quiet placeholder waveform.
- Image source unavailable: render fallback fill.
- Derivative job completion should refresh only the affected media id.
- Errors may show a small corner indicator later, but the first pass should avoid
  converting the whole clip into an error banner.

## Data and IPC

The existing `getMediaThumbnail(mediaId)` returns one base64 middle thumbnail and
is optimized for media-pool thumbnails. Keep it for existing callers.

Add a new timeline-oriented thumbnail manifest API:

```ts
getMediaThumbnails(mediaId) -> {
  frames: Array<{
    index: number;
    tUs: number;
    path: string;
  }>;
}
```

Expected behavior:

- Return `not_ready` when the thumbnail job has not produced the cache yet.
- Return paths for the current ten cached thumbnail files.
- `tUs` is the representative source timestamp for each frame.
- The renderer converts each `path` with `convertFileSrc(path)` and lets the
  browser image loader fetch the bytes.
- Keep this API compatible with future denser thumbnail caches.

## Frontend Structure

Recommended components:

- `TimelineVisualPreview`
  - dispatches per layer kind,
  - owns width-based preview gating,
  - renders fallback fills.
- `TimelineFilmstrip`
  - fetches and caches thumbnail manifests,
  - maps `src_in_us/src_out_us` to displayed frames,
  - listens for `media:job_complete` with `kind === "thumbnails"`.
- `TimelineWaveform`
  - fetches and caches waveform peaks,
  - draws to canvas,
  - listens for `media:job_complete` with `kind === "waveform"`.

Keep `LayerBlock` responsible for geometry, interaction, and chrome. It should
delegate the clip body content to these components instead of growing more
inline rendering branches.

## Visibility and Caching

First pass should use lightweight gating, not a full virtualization rewrite:

- Do not request preview resources when `layerWidthPx < 16`.
- Prefer requesting only when the layer block is in or near the viewport.
- Cache thumbnails by `mediaId`.
- Cache waveform peaks by `mediaId`.
- On derivative job completion, invalidate only the matching media id.
- Multiple clips from the same media should share fetched resources.

## Tests

Add or update focused tests around:

- `get_media_thumbnails` returns a manifest from the existing cache layout.
- Missing thumbnails return `not_ready`.
- `LayerBlock` still selects without seeking after preview content is added.
- Narrow clips avoid rendering labels and avoid preview requests.
- Filmstrip maps a trimmed `src_in_us/src_out_us` window rather than always
  showing the full source range.
- Waveform fallback renders when peaks are not ready.

Run the relevant renderer timeline tests and TypeScript/build checks after the
implementation.

## Implementation Notes

- Existing thumbnail job output is fixed at ten JPGs named `000.jpg` through
  `009.jpg`.
- Existing waveform command is `getWaveformPeaks(mediaId)`.
- Existing image loading should use `convertFileSrc`.
- Existing layer slice logic lives in `apps/desktop/src/renderer/timeline/geometry.ts`.
- Existing block/chrome logic lives in `apps/desktop/src/renderer/timeline/LayerBlock.tsx`.
- Existing media derivative job events are exposed as `media:job_complete`.
